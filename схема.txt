Сущности ER‑диаграммы системы управления рисками на стадиях проекта
Ниже — ключевые сущности, их атрибуты и смысловая роль в контексте управления рисками с учётом стадий проекта.

1. Проект
Атрибуты:

ID проекта (первичный ключ)

название

описание

дата начала

дата окончания

текущий статус (например, «инициация», «планирование», «исполнение», «мониторинг», «завершение»)

бюджет

приоритет

Роль: центральный объект, к которому привязаны все риски, меры управления и стадии.

2. Стадия проекта
Атрибуты:

ID стадии (первичный ключ)

название стадии (например, «инициация», «планирование», «исполнение», «мониторинг и контроль», «завершение»)

описание

порядковый номер в жизненном цикле проекта

дата начала

дата окончания

статус («запланирована», «в работе», «завершена»)

Связь с проектом: один проект включает несколько стадий (связь «один‑ко‑многим»).

3. Риск
Атрибуты:

ID риска (первичный ключ)

название

описание

вероятность возникновения (например, шкала от 1 до 5)

потенциальное влияние (шкала от 1 до 5 или денежное выражение)

уровень риска (рассчитывается как вероятность × влияние)

статус («идентифицирован», «в работе», «устранён», «закрыт»)

дата идентификации

дата устранения (если применимо)

Связи:

с проектом (один проект — много рисков);

со стадией проекта (один риск может быть актуален для одной или нескольких стадий).

4. Категория риска
Атрибуты:

ID категории (первичный ключ)
Desktop version

название (например, «технические», «финансовые», «организационные», «внешние»)

описание

Связь с риском: одна категория включает много рисков (связь «один‑ко‑многим»).

5. Мера управления риском (контрольное мероприятие)
Атрибуты:

ID меры (первичный ключ)

название

описание

стоимость реализации

срок реализации

ответственный сотрудник

статус («запланирована», «в работе», «реализована», «отменена»)

Связи:

с риском (одна мера может относиться к нескольким рискам — связь «многие‑ко‑многим»);

со стадией проекта (мера может быть запланирована на конкретную стадию).

6. Сотрудник
Атрибуты:

ID сотрудника (первичный ключ)

ФИО

должность

email

телефон

отдел

Связи:

с мерой управления (один сотрудник отвечает за несколько мер);

с проектом (один сотрудник может участвовать в нескольких проектах).

7. Событие риска
Атрибуты:

ID события (первичный ключ)

дата и время возникновения

описание

статус («подтверждено», «отклонено», «в анализе»)

ссылка на риск

ссылка на стадию проекта (когда событие произошло)

Связь с риском: один риск может иметь несколько событий (связь «один‑ко‑многим»).

8. Отчёт по рискам
Атрибуты:

ID отчёта (первичный ключ)

дата создания

период отчёта (даты начала и окончания)

статус («черновик», «на согласовании», «утверждён»)

ссылка на проект

ссылка на стадию проекта (если отчёт формируется по конкретной стадии)

Связь с проектом: один проект — много отчётов (связь «один‑ко‑многим»).

9. План реагирования на риск
Атрибуты:

ID плана (первичный ключ)

описание стратегии (например, «избежание», «снижение», «передача», «принятие»)

список мер управления

ответственные

сроки реализации

статус плана

Связь с риском: один риск — один план реагирования (связь «один‑к‑одному» или «один‑ко‑многим», если для риска несколько планов по стадиям).

10. Мониторинг риска
Атрибуты:

ID мониторинга (первичный ключ)

дата проверки

оценённая вероятность (на момент проверки)

оценённое влияние (на момент проверки)

текущий уровень риска

комментарии

ссылка на риск

ссылка на стадию проекта (на которой проводился мониторинг)

Связь с риском: один риск — много записей мониторинга (связь «один‑ко‑многим»).

Ключевые связи между сущностями
Сущность 1	Связь	Сущность 2	Пояснения
Проект	1 : N	Стадия проекта	Один проект состоит из нескольких стадий.
Проект	1 : N	Риск	Один проект имеет много рисков.
Стадия проекта	1 : N	Риск	Одна стадия может иметь риски, специфичные для неё.
Риск	1 : N	Событие риска	Один риск может реализоваться несколько раз.
Риск	1 : N	Мониторинг риска	По одному риску ведётся многократный мониторинг.
Риск	1 : 1 или 1 : N	План реагирования	Для каждого риска есть план (или несколько — по стадиям).
Риск	N : M	Мера управления	Одна мера может применяться к нескольким рискам; один риск может управляться несколькими мерами.
Мера управления	1 : N	Сотрудник	Одна мера закреплена за одним сотрудником; сотрудник может отвечать за несколько мер.
Проект	1 : N	Отчёт по рискам	По одному проекту формируется много отчётов (в т. ч. по стадиям).
Стадия проекта	1 : N	Отчёт по рискам	Отчёт может быть привязан к конкретной стадии.
Примечания
Первичные ключи (ID) обеспечивают уникальность записей в каждой сущности.

Внешние ключи (например, проект_id в сущности «Риск») реализуют связи между таблицами.

Кардинальность связей (1 : 1, 1 : N, N : M) отражает бизнес‑логику: например, один риск может быть актуален для нескольких стадий, а одна стадия — включать много рисков.

Для связи «многие‑ко‑многим» (например, «Риск» ↔ «Мера управления») обычно вводится ассоциативная сущность (например, «Риск_Мера») с внешними ключами и дополнительными атрибутами (сроки, ответственность и т. п.).
