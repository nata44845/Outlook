ER‑диаграмма системы управления рисками по стадиям проекта (со справочниками)
Ключевая особенность: наличие справочников (статичных классификаторов) для унификации данных и явная привязка рисков к стадиям проекта.

Основные сущности
Проект

Атрибуты:

project_id (PK)

название

описание

дата_начала

дата_окончания

статус («активен», «заморожен», «завершён»)

бюджет

Связь: 1 → N со стадиями, рисками, отчётами.

Справочник стадий проекта (статичный классификатор)

Атрибуты:

stage_type_id (PK)

код_стадии (например, «INIT», «PLAN», «EXEC»)

название («Инициация», «Планирование», «Исполнение»)

описание

порядковый_номер

Роль: задаёт типовой набор стадий для всех проектов. Не изменяется в процессе работы.

Стадия проекта (конкретный экземпляр стадии в проекте)

Атрибуты:

stage_id (PK)

project_id (FK)

stage_type_id (FK)

дата_начала_фактическая

дата_окончания_плановая

дата_окончания_фактическая

статус («запланирована», «в работе», «завершена»)

Связь: 1 → N к рискам; 1 ← 1 к справочнику стадий.

Справочник рисков (типовой перечень рисков для стадий)

Атрибуты:

risk_type_id (PK)

stage_type_id (FK)

название («Задержка поставок», «Превышение бюджета»)

описание

типичная_вероятность (1–5)

типичное_влияние (1–5)

Роль: стандартизирует риски для каждой типовой стадии. Позволяет повторно использовать шаблоны.

Риск (конкретный риск в контексте стадии проекта)

Атрибуты:

risk_id (PK)

stage_id (FK)

risk_type_id (FK)

вероятность_текущая (1–5)

влияние_текущее (1–5)

уровень_риска (вероятность × влияние)

статус («идентифицирован», «в работе», «закрыт»)

дата_идентификации

комментарий

Связь: 1 → N к мероприятиям и событиям; 1 ← 1 к справочнику рисков.

Мера управления (мероприятие)

Атрибуты:

measure_id (PK)

risk_id (FK)

название

описание

стоимость

срок_реализации

ответственный_id (FK к Сотруднику)

статус («запланировано», «в работе», «завершено»)

Связь: 1 → 1 к риску; 1 ← 1 к сотруднику.

Сотрудник

Атрибуты:

employee_id (PK)

ФИО

должность

email

отдел

Связь: 1 → N к мерам управления.

Событие риска

Атрибуты:

event_id (PK)

risk_id (FK)

дата_времени

описание

ущерб_фактический

статус («произошло», «отклонено»)

Связь: 1 → 1 к риску.

Отчёт по рискам

Атрибуты:

report_id (PK)

project_id (FK)

stage_id (FK, опционально)

дата_создания

период_отчёта (от, до)

статус («черновик», «утверждён»)

содержимое (текст/ссылка)

Связь: 1 → N к проектам; 0 → 1 к стадии.

План реагирования

Атрибуты:

plan_id (PK)

risk_id (FK)

стратегия («избежание», «снижение», «передача», «принятие»)

список_мер (ссылки на measure_id)

сроки_реализации

ответственный_id (FK)

Связь: 1 → 1 к риску.

Ключевые связи (с типами)
Сущность 1	Тип связи	Сущность 2	Пояснение
Проект	1 : N	Стадия проекта	Проект состоит из нескольких стадий.
Справочник стадий	1 : N	Стадия проекта	Каждая типовая стадия может быть использована во многих проектах.
Стадия проекта	1 : N	Риск	На каждой стадии возникает несколько рисков.
Справочник рисков	1 : N	Риск	Один типовой риск может порождать несколько конкретных рисков в проектах.
Риск	1 : 1	План реагирования	Для каждого риска есть один план.
Риск	1 : N	Мера управления	Один риск может управляться несколькими мерами.
Риск	1 : N	Событие риска	Один риск может реализоваться несколько раз.
Мера управления	1 : 1	Сотрудник	За каждой мерой закреплён ответственный.
Проект	1 : N	Отчёт по рискам	По проекту формируется несколько отчётов.
Стадия проекта	0 : N	Отчёт по рискам	Отчёт может быть привязан к конкретной стадии.
Особенности модели
Разделение справочников и экземпляров

Справочники (Справочник стадий, Справочник рисков) содержат типовые данные (не меняются в процессе работы).

Экземпляры (Стадия проекта, Риск) — конкретные записи для каждого проекта.

Привязка рисков к стадиям

Каждый риск связан с конкретной стадией проекта (stage_id), а не с проектом в целом.

Типовые риски из справочника привязываются к типовым стадиям (stage_type_id → risk_type_id).

Гибкость для повторных проектов

Можно использовать один справочник рисков для разных проектов, адаптируя их под конкретные стадии.

Рекомендации по реализации
Первичные ключи (PK): уникальные идентификаторы для каждой сущности.

Внешние ключи (FK): обеспечивают связи и целостность данных.

Нотация: для визуализации используйте Crow’s Foot (прямоугольники для сущностей, линии с «вилками» для связей).

Атрибуты статуса: позволяют отслеживать жизненный цикл объектов (например, статус риска или стадии).
